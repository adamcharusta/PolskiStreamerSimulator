# Technical Decision Register

Status: **technical interview decisions**, 2026-10-12. This register distinguishes user-confirmed choices from implementation defaults and deployment inputs. Detailed behavior lives in [Technical Architecture](technical-architecture.md) and [Technology Stack](technology-stack.md). Update the affected documents when a decision changes.

## Implementation Defaults to Validate

- Target .NET 10 LTS with Wolverine HTTP endpoints in ASP.NET Core.
- Use both `WolverineFx.Http.FluentValidation` for HTTP requests and `WolverineFx.FluentValidation` for CQRS messages, avoiding duplicate validator registrations. Generate OpenAPI with the ASP.NET Core generator and Wolverine command before Orval runs.
- A service worker may cache static assets for the optional PWA, but game actions require a live connection. Store only anonymous access material and the most recent confirmed display state in the browser; SQL Server owns careers.
- Test the two most recent major desktop versions of each named browser, plus current Android Chrome and current/previous iOS Safari.
- Inspect the existing ingress first. k3s packages Traefik by default; use it unless host inventory or an existing proxy gives a reason to choose another ingress. Keep SQL Server and Vault private.
- Consider SQL Server 2025 Express for the new database instance if VPS capacity and edition limits fit. Use separate staging and production databases/logins in one instance to avoid duplicate database processes on the shared VPS.
- Rehearse SQL Server restores from off-host backups. Give staging a separate namespace, database, Vault path, credentials and domain.
- After restoring an older backup, apply the six-month unfinished and 12-month finished retention rules before reopening public access; test that expired careers do not reappear.
- Issue individual staging tester credentials through a reverse proxy or equivalent access gate; do not reuse game or production administrator credentials. Define the test-data policy before inviting testers.
- Use a private Discord webhook or bot credential for operational alerts; include service, environment, timestamp, and a short error category, but no player data, career secrets, or database credentials.
